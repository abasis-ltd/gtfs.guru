What “baseline” means

The specification revision is the exact commit of gtfs/spec/en/reference.md whose files, fields, and enum values this build was checked against. The canonical baseline is the MobilityData validator release whose published rule set this build's notice codes were compared against.

Together they are what GTFS Guru answers for: any difference from them is either implemented, or listed on this page as an accepted difference. A weekly job compares both upstreams against this build and reports anything new, so this page going stale is a build failure rather than an oversight. Every JSON report carries the same two identifiers in its summary, so a stored report says which upstream state produced it.

What’s new since 1.0.0

Upstream additions dated after GTFS Guru 1.0.0 (2026-07-28), with the support status of each. Differences that are not fully supported are listed further down regardless of age, so an open gap never ages off this page.

transfers.txt/min_transfer_time

SupportedNeeds --thoroughSince 1.0.0

min_transfer_time became Conditionally Required

The reference changed min_transfer_time from Optional to Conditionally Required: it is now Required when transfer_type is 2. gtfs.guru already enforced exactly that condition, so no behaviour changed.

Reported as missing_required_field

Upstream: google/transit#640, 2026-08-17

The canonical validator has published no release since v8.0.1 on 2026-05-12, so its rule set is unchanged in this window.
