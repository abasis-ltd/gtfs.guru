Diagnosis

What this notice means

The reported rows have an identical ID or identical combination of key fields.

Operational effect

Why it matters

An app may reject the records or choose a row unpredictably.

Scope

Files to check and report fields

Use the file or input resource identified in the report. Check the message and available context fields; runtime failures may not identify a GTFS row.

Repair

How to fix it

  1. 1

    Compare oldCsvRowNumber and newCsvRowNumber in filename, using the reported key fields.

  2. 2

    Remove a true duplicate. For different entities, correct the key and update affected references. For a compound key, such as trip_id plus stop_sequence, check the whole combination.

  3. 3
    Check the result

    After a repair, rebuild the archive and validate it again. Confirm that the affected records are correct and that no new related notices appeared. A reviewed warning or informational notice may remain when it describes intentional, supported data.
