Diagnosis

What this notice means

This notice is emitted for values protected with double quotes since whitespaces for non-protected values are trimmed automatically by CSV parser.

The validator strips whitespaces from protected values. We do not see any use case when such a whitespace may be needed. On the other hand, some real-world feeds use trailing whitespaces for some values and omit them for the others. This is causing the largest problem when a primary key and a foreign key differ just by a whitespace: it is clear that they are intended to be the same, that is why we always strip whitespaces.

Operational effect

Why it matters

Identifiers that differ only by spaces can break foreign-key matching, while rider-facing text may display unevenly.

Scope

Affected files and report fields

Repair

How to fix it

Trim whitespace at both ends of the value in the source system; do not rely on the validator to normalize the published feed.

  1. 1
    Locate the record

    Open stops.txt and use the report fields below to find the exact row.

  2. 2
    Change the source data

    Trim whitespace at both ends of the value in the source system; do not rely on the validator to normalize the published feed.

  3. 3
    Validate again

    Rebuild the GTFS archive and confirm that leading_or_trailing_whitespaces no longer appears for the record.

Worked example

Bad row and correction

Before

stop_id,stop_name

After

stop_id,stop_name
S1,Central Station
