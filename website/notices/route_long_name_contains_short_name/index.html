Diagnosis

What this notice means

In routes.txt, route_long_name should not contain the value for route_short_name, because when both are provided, they are often combined by transit applications. Note that only one of the two fields is required. If there is no short name used for a route, use route_long_name only.

Good examples:

Operational effect

Why it matters

Apps commonly combine both fields, producing labels such as “10 — Route 10 Downtown”.

Repair

How to fix it

Keep the identifier in route_short_name and describe only the destination or corridor in route_long_name.

  1. 1
    Locate the record

    Open routes.txt and use the report fields below to find the exact row.

  2. 2
    Change the source data

    Keep the identifier in route_short_name and describe only the destination or corridor in route_long_name.

  3. 3
    Validate again

    Rebuild the GTFS archive and confirm that route_long_name_contains_short_name no longer appears for the record.
